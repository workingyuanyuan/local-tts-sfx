# 音效（MOSS-SoundEffect v2.0）驗收

日期：2026-11-17。對象：音效工作（`POST /v1/sfx/jobs`、`adapters/moss_sfx.py` 與 `workers/moss-sfx/worker.py` 的子程序、`tts sfx`／`tts sfx-clips`、MCP 音效工具、`scripts/install_agent_rules.sh`）。腳本：`scripts/sfx_run.sh`（啟動本 checkout 的伺服器於 8791 埠並執行 `scripts/sfx_smoke.py`）、`scripts/sfx_mcp_stdio.py`。原始紀錄在 `outputs/sfx-accept-main`（不進 repo）。

## 方法

- 機器：RTX 5090 Laptop GPU 24 GB，WSL2，接電源。開始時 GPU 用量 651 MiB，正式服務（8765 埠）未載入模型。
- 版本：合併到 `main` 之後的程式，`torch.compile` 開啟（預設），100 步。
- `sfx_run.sh` 依序做：單一音效（4 秒）、三個片段的工作（3、6.5、1.5 秒）、語音 → 音效 → 語音的切換。每個檔案檢查取樣率、長度、聲道數與是否靜音；切換後檢查載入的模型與是否留下子程序；全程每 500 ms 取樣 `nvidia-smi`。
- 單元測試：`.venv/bin/python -m pytest -q tests`，不需要 GPU（子程序由 `tests/fake_sfx_worker.py` 代替）。

## 結果

`sfx_run.sh`：ALL PASS。單元測試：236 個通過。

| 項目 | 數值 |

| 每個音效的生成時間 | 13.96–14.34 秒（1.5 到 6.5 秒的片段都一樣） |
| 載入（第一次，含啟動子程序） | 36.2 秒 = 載入 23.6 秒 + 編譯暖機 12.0 秒 |
| 載入（從語音模型切換過來） | 39.1 秒 = 載入 17.4 秒 + 編譯暖機 21.3 秒 |
| 單一音效，從送出到完成（含第一次載入） | 50.3 秒 |
| 三個片段的工作（模型已載入） | 42.8 秒 |
| 語音模型載入（從音效切換回來） | 17.4、18.3 秒 |
| GPU 用量，音效模型載入後 | 15,231–16,340 MiB |
| GPU 用量，全程最高取樣 | 16,394 MiB |
| GPU 用量，語音模型載入後 | 約 13,285 MiB |

- **長度不影響時間**：模型每次都對 30 秒的潛在表示去噪，再裁切成要求的長度。
- **切換**：三次切換後載入的模型都正確，音效子程序在卸載時結束，沒有殘留；結束時 GPU 回到語音模型的用量。兩個模型合計約 30 GB，無法同時載入。
- **估計時間**：第一個工作的初始估計是 160 秒（尚無實測值時的預設），量到一次後變成 50.4 秒（載入 36.2 秒 + 每片段 14.2 秒）。
- **輸出格式**：全部是 48 kHz、單聲道，長度與要求相符，沒有靜音檔。

### 其他介面

- `scripts/sfx_mcp_stdio.py`（經 stdio 啟動 `tts-mcp`，呼叫四個音效工具，包含 `pending` 後接續）：ALL PASS。這是合併前在 `sfx` 分支上跑的，之後只改了規則的安裝方式。
- `tts sfx`、`tts sfx-clips` 實際生成成功；已存在的檔案在沒有 `--overwrite` 時拒絕；`-s 40` 回 `invalid_seconds`；`-s nan` 回 JSON 的 `invalid_request`。

### 內容

格式檢查無法判斷聲音是否符合描述。把 7 個輸出交給 Gemini 聽（不提供提示詞，只要求描述聽到的聲音）：6 個相符，1 個不符。不符的是「heavy wooden door creaking open」（seed 5），被聽成引擎聲。樣本只有 7 個，而且判斷者也是模型，不能當成品質的結論；規則因此要求 Agent 檢查音效，不符時換 `seed` 或把描述寫得更具體。

### 審查

Codex（gpt-6.1-sol）審查兩輪，共 15 個問題（寫入時阻塞、損壞的標頭使 GPU 執行緒結束、卡住的子程序未被停止、最後一個片段失敗時忽略取消、安裝腳本的標記檢查與部分寫入、MCP 逾時路徑未檢查工作種類等），全部修正並加了回歸測試。審查者在唯讀沙箱中無法執行測試，結論來自閱讀程式碼與小型實驗。

## 已知限制

- **用電池時慢約三倍**：筆電用電池時 GPU 功率被限制在約 18–26 W，同樣的片段要 42–53 秒。
- **沒有 C 編譯器時無法編譯**：`torch.compile` 需要 gcc；未編譯時每個片段至少 36 秒。該數字是在 GPU 有其他負載時量的，沒有乾淨的未編譯數字。
- **第一次編譯**：編譯快取是空的時候，暖機曾量到約 100 秒（獨立腳本，非本服務）；本次兩次暖機是 12.0 與 21.3 秒，快取已存在。
- **其他程式佔用 GPU 時**：語音模型（約 13.6 GB）或 Windows 端的程式佔用顯存時，音效模型放不進 24 GB，片段曾要 40–90 秒。
- **只測了一台機器**，音效長度只測到 6.5 秒；30 秒上限來自模型，未在本服務實測。

## 規則的安裝方式

規則原稿只有 skill（`agent-rules/skills/narration`、`sound-effects`），由安裝腳本寫到 `~/.claude/skills` 與 `~/.codex/skills`。先前版本在 `~/.codex/AGENTS.md` 寫入標記區塊，那會進入每個專案的上下文；現在安裝腳本只會移除那些舊區塊。在暫存的家目錄測過：安裝四個 skill、移除兩個舊區塊並保留其餘內容與備份、重複執行結果不變、沒有舊區塊時不建立也不修改 `AGENTS.md`、標記不成對時什麼都不改。
