# Sound effects (local model)

The same local service (MCP server `local-tts`) also generates sound effects (MOSS-SoundEffect v2.0, 48 kHz mono, ≤ 30 s per clip). When a video, animation, game prototype, UI demo or audio story needs non-speech sound — effects, foley, ambience, transitions, UI sounds; 音效、環境音、擬音 — generate it instead of leaving gaps. Not for speech (narration rules above) and not for background music or songs.

- Tools: `generate_sound_effect_clips` (several effects in one job, each to `<output_dir>/<id>.<format>`: the normal way, one call per deliverable), `generate_sound_effect` (one effect to `output_path`), `get_sound_effect_job` / `get_sound_effect_clips` for pending jobs; `cancel_speech_job`, `list_speech_jobs`, `unload_model`, `list_models`, `tts_status` cover these jobs too. Without MCP: `tts sfx "PROMPT" -s 3 -o /abs/path/door.wav --json --timeout 45` or `tts sfx-clips effects.json -d /abs/dir --json --timeout 45` (effects.json `[{"id": "door", "prompt": "...", "seconds": 3}]`); exit 3 = still running: run the returned `fetch_command` with `--timeout 45` until it exits 0 (4: follow `recovery`); never rerun the submission.
- Prompts: describe the source, action, material, space and distance concretely, in English or Chinese ("large wooden door slams in a stone hallway, short echo"); no moods, words or melodies. `seconds` is required for every clip (≤ 30); limits per call: 100 clips, 300 s, 2,000 characters per prompt. Absolute `output_dir` inside the project (e.g. `assets/sfx/`).
- Batching: put every effect of a deliverable in ONE clips call (the model loads once; the first clip after a load is slow, compile warm-up). Do all narration first or last, never interleaved: switching between the speech and sound-effect models unloads one and loads the other (tens of seconds each way).
- Placement: you know the timeline; place each effect with ffmpeg, e.g. `ffmpeg -i video.mp4 -i narration.wav -i door.wav -i rain.wav -filter_complex "[2:a]adelay=4200:all=1[d];[3:a]volume=0.4[r];[1:a][d][r]amix=inputs=3:duration=longest:normalize=0[a]" -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k out.mp4` (`duration=longest` keeps an effect placed after the narration ends, so make the video at least that long; `normalize=0` keeps each input's level; `volume=`, `atrim`, `afade` as needed). Effects are mono 48 kHz.
- Checking (you cannot hear): duration with `ffprobe -v error -show_entries format=duration -of csv=p=0 f.wav`; loudness with `ffmpeg -i f.wav -af volumedetect -f null -` (max_volume below about -40 dB ≈ silence); where an audio-capable model is available, ask it to describe the clip without telling it the prompt. Mismatch → regenerate only that clip (`overwrite: true`) with another `seed` or a more concrete prompt. Report paths, durations, prompts and seeds.
- Jobs and errors: `pending` → call `next.tool` with exactly `next.arguments`; never resubmit a pending job (`list_speech_jobs` finds a lost job_id). Errors with a `job_id` carry `recovery`: follow it. `wrong_job_kind` → call the tool it names. `partial` → follow its `recovery`: regenerate only clips that failed in generation (`stage: "synthesis"`); clips with `stage: "delivery"` exist on the server, so fetch them again with the getter it names. `warnings` (e.g. running uncompiled) → slower, not wrong. `sfx_worker_not_installed` / `model_weights_missing` → tell the user the `install_command` / `download_command`. `sfx_worker_failed` / `sfx_worker_timeout` → submit once more, then tell the user. `server_unreachable` → `systemctl --user start local-tts`.
